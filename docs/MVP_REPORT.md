### 공용 모듈 (비전앱과 공유)

```
packages/
  core-domain       타입·스키마 버전 (단일 소스)
  exercise-library  운동 30종, 추천 규칙, 유료 게이트, 모션 속도 계산
  workout-engine    순수 리듀서 상태머신 — repSource 'timer'(음성) / 'external'(비전)
  metrics           볼륨·칼로리·부위 분포·캘린더·스트릭
  storage           IndexedDB(Dexie, DB명 hc-db), 진행 세션 복구, 백업
apps/voice-coach    PWA (React + Vite)
```

리팩토링을 줄이기 위해 지킨 원칙:
- **엔진은 시계를 주입받는 순수 함수**. 상태가 JSON이라 저장·복원·테스트가 같은 코드로 됨. 비전앱은 `repSource: 'external'`로 같은 엔진에 `REP` 이벤트만 보내면 됨 (테스트 완료)
- **음성·백그라운드·결제는 앱 쪽 파일 3개에 격리** (`lib/voice.ts`, `lib/keepAlive.ts`, `lib/billing.ts`). PWA로 안 되는 게 확인되면 이 3개만 네이티브 구현으로 교체
- 모든 저장 레코드에 `schemaVersion`, 세트 기록에 `source: timer | vision | manual`

| 단계 | 테스트 | 결과 |

| E2E (실제 빌드, 헤드리스 Chromium, 가짜 시계) | 설문→제안→선택→루틴→홈→운동→요약→캘린더, 새로고침 복구, 폼팩터 4종 | 23 통과 |

**단위 60 + E2E 23 = 83개 전부 통과.** 타입 검사 오류 0.

테스트 중 발견해 고친 것:
- 백그라운드 복귀 시 지나간 반복 숫자를 몰아서 읽던 문제 → 지난 단계의 음성 큐는 버리고 상태 큐만 유지
- 마지막 세트에서 지쳐 중량을 낮추면 그게 다음 기본값이 되던 문제 → 완료 세트에서 가장 많이 쓴 중량(동률이면 무거운 쪽)을 기억
- 휴식 경고 문구가 운동 사이에도 "10초 후 시작"으로 나오던 문제
- 근력 목표에서 고립 운동(레터럴 레이즈 등)도 6회로 처방되던 문제 → 고립 운동은 최소 10회
- 근력 중급자에게 데드리프트·RDL·힙쓰러스트가 함께 추천되던 문제 → 동작 패턴 중복 감쇠

## 3. 우려사항 — 실기기에서 중점 확인할 것

### 🔴 출시 전 반드시 해결

#### 3-1. 화면 꺼짐·다른 앱 사용 중 음성 카운트 (가장 큰 리스크)
- **왜**: Android Chrome은 숨겨진 페이지의 타이머를 늦추고(5분 뒤 1분 단위까지), 음성합성이 백그라운드에서 끊길 수 있음. TWA로 스토어에 올려도 **엔진은 같은 Chrome**이라 결과가 같음
- **넣어 둔 대응**: Wake Lock, 저음량 루프 오디오(소리 나는 페이지로 유지), Media Session, 화면 복귀 시 경과 시간 따라잡기, 진행 상태 상시 저장
- **확인 방법**
  1. 홈 화면에 설치한 앱으로 운동 시작 → 전원 버튼으로 화면 끄기 → 3분 이상 음성이 계속 세는지
  2. 운동 중 유튜브·카톡으로 전환 → 같은 확인
  3. 설정 → **백그라운드 진단**에서 "최대 타이머 간격"이 1초 이하인지, "2초 넘게 멈춤" 횟수
- **실패하면**: Capacitor로 감싸 네이티브 포그라운드 서비스 + 네이티브 TTS로 `voice.ts`·`keepAlive.ts`만 교체 (엔진·화면은 그대로). 이 경우 결제도 Play Billing 라이브러리로 바뀌므로 **결제 서버 작업 전에 이 결론을 먼저 내는 게 순서상 유리**

#### 3-2. Google Play 결제 서버 검증
- Play는 **3일 안에 승인(acknowledge)되지 않은 구매를 자동 환불**. 클라이언트만으로는 불가
- 필요한 것: 서버(예: Cloudflare Worker) + Play Developer API 서비스 계정 → 구매 토큰 검증·승인, 구독 갱신·취소 알림(RTDN) 수신
- 앱 쪽은 `VITE_BILLING_VERIFY_URL`만 설정하면 연결되도록 준비됨. 미설정 시 테스트 모드(로컬 승인)
- 웹 미리보기에서는 결제 버튼이 꺼지고 안내가 나옴(정상). 프로 기능 확인은 **설정 하단 버전 글자를 7번 탭** → 테스트용 프로 켜기/끄기

#### 3-3. 3D 모션 영상 미제작
- 현재 모션 모드는 근육 맵이 반복에 맞춰 강약을 주는 대체 화면. 유료 가치의 핵심이라 영상 없이 유료 출시는 어려움
- 영상 경로만 데이터에 넣으면(`motion.video`, `motion.thumb`) 재생·속도 동기화·잠금이 바로 동작
- 무료 체험 모션: 인기 상위 5종(레그 프레스, 랫풀다운, 체스트 프레스 머신, 벤치 프레스, 백 스쿼트). 나머지는 잠금 화면 확인용

### 🟡 실기기에서 판단이 필요한 것

| # | 확인할 것 | 어떻게 보면 되나 | 판단에 따라 |
|---|---|---|---|
| 1 | 한국어 음성 품질·지연 | 설정 → 음성 들어보기 / 2초 간격 15회로 운동 | 갤럭시 기본 Samsung TTS에 한국어 음성이 없으면 소리가 안 남. 안내 토스트 확인. 2초 간격에서 "스물셋"이 밀리면 사전 녹음 음성으로 교체 |
| 2 | **듣던 음악이 멈추는지** | 음악 앱 재생 → 운동 시작 | 유지용 오디오가 오디오 포커스를 가져가 음악이 멈출 수 있음. 설정의 **"화면이 꺼져도 계속 세기"**를 끄면 해결되지만 대신 화면을 켜 둬야 함 |
| 3 | 플립 커버화면 | Good Lock → MultiStar 설정 후 접은 상태로 운동 (설정 → 커버화면 사용법) | 미니 화면 글자 크기, 버튼 2개 누르기 편한지, 스와이프 |
| 4 | **주머니 속 오작동** | 폰을 주머니에 넣고 세트 진행 | 화면 탭 = 세트 완료라서 잘못 눌릴 수 있음. 설정의 "화면을 눌러 세트 끝내기"로 끌 수 있음. 기본값을 끌지 결정 필요 |
| 5 | 세는 방식 | 운동 시작 | 지금은 **한 회를 마칠 때** "하나"를 셈(시작 후 2~6초 뒤 첫 숫자). 시작 순간 세는 방식을 원하면 엔진 1줄 변경 |
| 6 | 운동 사이 대기 | 한 운동 끝 → 다음 운동 | 세트 사이는 자동 시작, **운동 사이는 "시작"을 눌러야** 시작(기구 이동·세팅 시간 차이 때문). 자동으로 할지 결정 |
| 7 | 이어폰 버튼 | 갤럭시 버즈 탭 | 다음 = 지금 단계의 다음 동작(시작/세트 완료/휴식 건너뛰기), 이전 = 나중에, 재생·일시정지. 버즈 제스처 설정에 따라 다를 수 있음 |
| 8 | 폴드 펼침 화면 | 펼쳐서 운동 | 와이드 레이아웃이 왼쪽 링이 작게 보임. 실제 화면 보고 크기 조정 |
| 9 | 칼로리 수치 체감 | 요약 화면 | MET × 체중 × 시간 추정치. 웨어러블 값과 많이 다르면 보정 계수 검토 |

### 🔵 다음 단계에서 리팩토링을 피하려면 지금 결정할 것

1. **분할 루틴(상체/하체 등)**: 현재는 분할을 *제안만* 하고 루틴은 1개. 저장 구조는 루틴 여러 개를 지원하므로 화면만 추가하면 됨. 비전앱이 루틴을 쓰기 전에 "하루 = 루틴 1개" 구조로 갈지 확정 필요
2. **PoseCoach와 DB 공유**: 같은 도메인(solo-main)에 배포했으므로 PoseCoach가 `hc-db`(@hc/storage)를 쓰면 기록이 바로 합쳐짐. PoseCoach 쪽 저장 구조 이전 작업 필요
3. **운동 100종 확장 방식**: 지금은 30종 데이터가 앱에 들어 있음. 앱 업데이트 없이 추가하려면 운동 데이터 JSON + 모션 영상을 CDN(R2 등)에서 받도록 바꿔야 함. `LIBRARY_VERSION`은 준비됨
4. **추천 규칙 검수**: 규칙 기반이라 트레이너 1회 검수 권장 (예: 초급자에게 컨벤셔널 데드리프트가 추천될 수 있음, 입문자는 제외 처리됨)
